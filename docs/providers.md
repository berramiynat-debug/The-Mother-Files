## Field ownership and failures

- **TVmaze** owns cast attribution, show dates, summaries, and series order. Episode details verify the embedded show ID from the direct episode request. The episode list supplies optional previous and next links. Actor details are restricted to people in the show’s canonical cast.
- **TMDB** owns optional media paths. The server accepts only GET requests for fixed show ID 1100 and small integer season/episode bounds. The browser receives filtered data and never supplies or receives the credential. Successful proxy results are cached.
- **HIMYM Character API** contributes attributed metadata. The app validates and deduplicates aliases and quote samples. It discards quotes with missing authors, missing lines, or long excerpts.
- **Original fiction** drives mysteries, dialogue, and pub activities. API failure affects only the dependent interactions. Provider-level failures and empty results have distinct UI.

## The Mosby Margins

The notebook uses a server-side `POST /api/hints` in Vite dev, Vite preview, and the Vercel Node function. It uses `openai/gpt-oss-20b` through Groq Chat Completions. [Groq model documentation](https://console.groq.com/docs/model/openai/gpt-oss-20b) · [Groq rate limits](https://console.groq.com/docs/rate-limits)

- Quick buttons and step-by-step hints use local rules. A custom request carries the question (up to 400 characters) and up to three recent successful chat exchanges. The notebook displays up to six exchanges and keeps them in browser memory for the current chapter.
- The server builds the case context from validated IDs and sends opened record contents, checked deductions, and the available action labels. Groq writes a short plain-text reply in the player’s language. The server checks referenced IDs against the opened records and returns their archive titles for display. Timeouts, missing credentials, invalid replies, and rate limits use the question-aware guided fallback.
- The function accepts same-origin browser requests and caps bodies at 16 KiB, provider calls at seven seconds, and completions at 512 tokens. Each running instance allows one outstanding request and six requests per minute per IP, with a total of 12 requests per minute and 150 per day. Vercel supplies the client IP when deployed. These counters reset with the process. Groq project quotas apply account-wide.
